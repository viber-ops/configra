# Use opaque high-entropy API Tokens

API Tokens use `cfg_<public-id>_<secret>`, where the public ID locates the record and the base64url Secret contains 32 bytes generated by `crypto/rand`. Plaintext is shown once; Configra stores only the public ID, display prefix, and SHA-256 Secret digest and compares digests in constant time. High random entropy makes a password KDF and reversible Token encryption unnecessary.

Machine Clients send Tokens only as `Authorization: Bearer` credentials over HTTPS; URL, Cookie, and body transport are unsupported, and Authorization values are redacted from application, SDK, and proxy logs. Rotation is create-overlap-revoke rather than mutation or a dedicated rotate operation.
