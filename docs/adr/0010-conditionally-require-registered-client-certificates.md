# Conditionally require registered Client Certificates

Every Machine Client request requires an Active, unexpired API Token authorized for the requested Environment. A Token's immutable creation-time `allow_without_mtls` flag defaults to false; when true, the same HTTPS listener accepts the request without a Client Certificate, and the Token may still be configured as non-expiring. Otherwise the request must present a Client Certificate that validates to the Client CA from Cold-start Configuration and exactly matches an Active public certificate registered in Configra. A presented invalid, unregistered, or revoked Certificate always rejects the request instead of downgrading it to Token-only Authentication. Certificates are issued externally and imported without private keys; Management verifies an imported leaf and optional chain against the same cold-start Client CA before storing the leaf fingerprint. Configuring that CA on Management does not enable browser mTLS. Multiple certificates may coexist for rotation, revocation is permanent, and API Server checks current credential state on every request. A Certificate is not bound to a particular Token, and revoking a Certificate cannot disable use of a Token that permits Token-only Authentication; that Token must be revoked separately.
