# Scope API tokens by Environment

Each API Token grants access only when its explicit allowlist contains the requested Environment, including all Config and Vault values in that Environment. Vault Namespace and Item Keys select values but never narrow or expand this grant. Its immutable creation-time `allow_without_mtls` flag defaults to false but may explicitly permit Token-only Authentication without weakening the Environment allowlist. An administrator may edit the allowlist, including leaving it empty; changes take effect on the next request and produce Audit Events. Archiving an Environment blocks access without deleting its grants, and Unarchive restores access to previously authorized Tokens after showing those Tokens to the administrator. Tokens default to 90-day expiry, may explicitly be created without expiry even in Token-only mode, and cannot be restored after revocation. Environment-only scoping deliberately avoids per-Config, per-Namespace, or per-Item policy, Secret flags, and complex RBAC in V1 while preventing a machine credential from crossing into unapproved runtime contexts.
