# Bound administrator sessions in Cold-start Configuration

Administrator Session limits are operator-owned deployment policy, so the Management Server reads `sessions.idle_timeout_minutes` (5–1440, default 30) and `sessions.lifetime_hours` (1–168, default 8) from Cold-start Configuration once at startup, and the API Server rejects the block. The Management UI shows the effective values read-only and never edits them (ADR-0001): every replica applies the same limits, and a live security policy is never weakened from a session it governs. A lifetime above the default keeps the `__Host-` Session Cookie across browser restarts. Roles and MFA are captured from signed claims at sign-in (ADR-0033), so the lifetime also bounds how long a demoted or removed administrator keeps access unless the session is invalidated; the 7-day ceiling keeps that window reviewable. An ended Session is recovered in place: the browser keeps unsaved work, offers sign-in in a separate tab, reloads if the signed-in identity or role changed, and warns before the idle timeout.
