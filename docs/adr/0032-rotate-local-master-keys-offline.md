# Rotate Local Master Keys in an offline transaction

Support operator-initiated Master Key rotation during a maintenance window: authenticate all stored encrypted records, rewrap their DEKs, replace the Crypto Sentinel and persist a system Audit receipt in one InnoDB transaction. Keep payloads, nonces, business Revisions, ETags and the `local-v1` envelope-format identifier unchanged; use no online keyring, background migration or automatic Secret replacement.

Encrypted writers lock and verify the Sentinel before other mutation locks; rotation locks it exclusively, and readiness verifies the active key. These guards protect current-code replicas holding a stale key, not older releases or arbitrary SQL writers: operators must stop all replicas and automated restarts, use independently verified database/key backups, and restart with the replacement key only after verification. A lost COMMIT acknowledgment is an unknown outcome, resolved by running the read-only doctor with each key; it must never be reported as a guaranteed rollback. One maintenance transaction is intentionally simpler than a resumable multi-key migration, whose need must be established by measured recovery-point size and downtime requirements.
