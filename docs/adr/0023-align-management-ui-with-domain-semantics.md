# Align Management UI with Domain semantics

Management UI ships in English and Simplified Chinese with one responsive information structure: Overview, Environments, Configs, Vault, Notifications, Access, Audit, and Administration. Administration owns API Tokens, Client Certificates, Notification Destinations, and read-only Deployment Status; Cold-start Configuration is never edited online. The top bar contains global search, theme, language, and session actions only; it does not duplicate destination or administration navigation from the sidebar. Light and dark themes use the same semantic surface hierarchy, persist the operator's selection, follow the operating-system preference before a selection exists, and give code syntax and diff states explicit contrast-aware colors. Environment visuals remain peer-level: a dense inventory opens a detail view of current Config revisions and Vault bindings, while Config and Vault inventories accept an exact Environment filter preserved in the hash query. Destructive lifecycle actions say Archive or Revoke. Overview reports only operationally useful facts: MySQL readiness, ClickHouse query availability, deduplicated recent Audit Events, resource counts, and Configs without an active Environment Revision. High-volume Access Events remain on the searchable Access page instead of becoming a low-signal “latest read” tile. Overview does not connect unrelated Revisions into a timeline, display uncollected placeholders, or decorate the page with an inapplicable protocol version.

Config pages expose Raw, Admin-only Resolved Preview, History, and a single deterministic Merge/Replace preview around a visible Revision rail. The rail keeps the latest eight shortcuts while every row in complete Config and Vault History opens that immutable snapshot; only the current Revision exposes edit controls. Vault uses a dense searchable table with Namespace and Environment filters; Namespace is displayed as one immutable identity segment rather than a folder, permission boundary, or separately managed resource. Vault Item pages select a Variant before showing its complete values, provide a copyable `{vault.<namespace>.<item>.<field>}` beside each Text and Secret Field, direct File Fields to the Client bytes API, and list only value-free current Config references. Removing a referenced Field or bound Environment requires an explicit impact confirmation but remains allowed because unresolved references are a supported staged-setup state. Config and Vault editors protect dirty drafts with native leave confirmation, preserve content on Conflict, map stable error codes to localized actions, expose a copyable Request ID, disable no-op/double submits, and report the resulting Revision. Viewer may read Raw Config and Vault metadata; Admin alone may request any Vault values, reveal or copy Secrets, download Files, edit complete Snapshots, and open Resolved Preview. Audit history uses ClickHouse-side metadata search and bounded pagination rather than loading the full history into the browser. The checked-in UI images are visual explorations of these rules, not a substitute for the Domain model.
