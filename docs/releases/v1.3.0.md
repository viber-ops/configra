# Configra v1.3.0

This release makes Config copies and templates easier and safer, replaces
expiring API Tokens without guesswork, and keeps administrators' work when a
session ends. Operators can now set administrator session limits. It remains
compatible with configra-go v1.2.0. The MySQL schema stays at **4**.

本版改进 Config 复制与模板、引导替换即将过期的 API Token，并在会话结束时保留管理员正在编辑的内容；
运维可在冷启动配置中设置管理员会话时长。SDK 保持 v1.2.0；从 v1.2.2 升级不需要数据库结构迁移。

## Changes / 变更

**Config copies and templates** (ideas from [#31](https://github.com/viber-ops/configra/pull/31); [#32](https://github.com/viber-ops/configra/pull/32), [#33](https://github.com/viber-ops/configra/pull/33))
- **Copy content** buttons on the Config editor and the Copy to environment
  form copy the source with Vault references, not resolved values.
- **Copy to environment** can edit the content before writing; the edit is
  committed as the target's first version (`expected_revision` 0) and keeps one
  operation ID across retries. **Show changes** diffs it against the source.
- Before any write, the content is checked against the chosen target with
  `POST /v1/configs/validate`: syntax errors block the copy and Vault
  references without a value in that Environment are listed. Environments that
  already have the Config are marked and cannot be chosen.
- Creating a Config can start from **any** existing Config as a template
  (searchable, never overwrites typed content), also via **New Config from this
  template** in the detail menu. Clone stays an exact, server-side copy.

**API Token replacement** ([#34](https://github.com/viber-ops/configra/pull/34))
- **Replace** opens a new Token with the same access: name, every active
  Environment grant, the mTLS setting and, for write-scoped Tokens, the exact
  Config and Namespace scopes. Rotation stays create-overlap-revoke (ADR-0019):
  the old Token keeps working until it is revoked from the replacement steps,
  which warn that revoking a write-scoped Token also revokes its deployment
  credentials.
- Tokens within 14 days of expiry show **Expires soon**, the Token list can show
  only those, and the Overview lists the soonest five for administrators.
- `GET /v1/api-tokens` accepts `expiring_within_days` (1–365).

**Administrator sessions** ([#35](https://github.com/viber-ops/configra/pull/35), [ADR-0035](../adr/0035-bound-administrator-sessions-in-cold-start-configuration.md))
- New optional Management-only Cold-start block:
  ```yaml
  sessions:
    idle_timeout_minutes: 30   # 5..1440
    lifetime_hours: 8          # 1..168; a lifetime above 8 h survives browser restarts
  ```
  Values are read at startup; set the same values on every Management replica.
  The API Server rejects the block. Deployment status shows the effective limits.
- When a session ends, the page now stays: a banner offers **Sign in in a new
  tab**, unsaved work is kept, and the page reloads if the signed-in identity or
  role changed. The UI warns two minutes before the idle timeout (with **Stay
  signed in**) and ten minutes before the session ends, and signing in returns
  to the page that asked for it. Actions after a session ends now say so instead
  of reporting a generic save failure.
- `/v1/me` adds `session_expires_at`, `session_idle_timeout_seconds` and
  `session_lifetime_seconds`.

**Usability** ([#37](https://github.com/viber-ops/configra/pull/37), idea from [#36](https://github.com/viber-ops/configra/pull/36))
- Row actions have a 30px target (WCAG 2.5.8) instead of bare 16px text buttons.

## Upgrade from v1.2.2 / 从 v1.2.2 升级

1. Preserve the current binary/image and configuration and take the usual
   verified backup.
2. Optionally add the `sessions` block to the **Management** configuration only;
   without it the limits stay at 30 minutes idle and 8 hours.
3. Restart Management, API and workers with the matching v1.3.0 build. Ports,
   Master Key and service-account grants are unchanged.
4. No `migrate` step or new MySQL/ClickHouse DDL is required. The database
   remains schema **4**.
5. Reload the Management page.

从更早版本升级，仍需依次完成 [v1.1.0](v1.1.0.md) 与 [v1.2.0](v1.2.0.md) 的迁移步骤。

## Rollback / 回退

v1.3.0 changes no stored data. **Remove the `sessions` block before rolling back
to v1.2.x**: earlier versions reject unknown configuration fields and would not
start. Rolling back otherwise only restores the previous UI and limits.

## Verification

The merged `main` commit passed CI including the ten-minute production-image
capacity gate and the three-node Kubernetes acceptance
([run 41954559312](https://github.com/viber-ops/configra/actions/runs/41954559312)).
Each change was also checked against the local stack before merging:
real-backend copy pre-checks and template loading, the four-Environment Token
replacement prefill and the `expiring_within_days` filter, and session recovery
with the real OIDC provider (a dropped session kept the form, signing in from a
new tab closed itself and the retried save succeeded). Server-side expiry at the
configured idle timeout is covered by unit tests of the session settings.
Publication does not upgrade or restart a user's production deployment
automatically.
