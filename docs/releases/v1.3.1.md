# Configra v1.3.1

This patch keeps the current version in view on Config pages, fixes their
layout on phones, stops rare 503 responses to concurrent automation writes and
updates the Go, Kubernetes and UI dependencies. It remains
compatible with configra-go v1.2.0. The MySQL schema stays at **4**, and no
configuration change is needed.

本版让 Config 页面始终显示当前版本，修复手机上的页面横向溢出和并发写入偶发的 503 错误，并更新 Go、Kubernetes 与界面依赖。
SDK 保持 v1.2.0；从 v1.3.0 升级不需要数据库结构迁移，也不需要修改配置。

## Changes / 变更

**Config pages** ([#38](https://github.com/viber-ops/configra/pull/38), ideas from [#36](https://github.com/viber-ops/configra/pull/36))
- The revision track wraps instead of scrolling sideways, so the current
  version stays in view with up to eight revisions.
- On a phone, long Config names wrap. A 390px-wide screen previously laid the
  page out 740px wide, so it scrolled sideways.
- Where there is room, the Environment picker puts its list and its search on
  one row: the Configs and Vault filters, the Config header and the template
  picker. Narrow form columns, such as Copy to environment, keep them stacked.

**Reliability** ([#44](https://github.com/viber-ops/configra/pull/44))
- Concurrent writes that create Vault Items in the same namespace, or that issue
  deployment credentials, no longer fail with 503 `service_unavailable` when
  MySQL picks one of them as a deadlock victim. The write is retried (up to four
  times, with a short random delay) and succeeds; its operation ID still applies
  it only once.

**Dependencies** ([#40](https://github.com/viber-ops/configra/pull/40), [#41](https://github.com/viber-ops/configra/pull/41), [#42](https://github.com/viber-ops/configra/pull/42))
- UI: React 19.3.1 and current CodeMirror releases. Every bundled package stays
  MIT with an unchanged license text.
- Server and CLI: ClickHouse client 2.50, NATS client 1.55, MySQL driver 1.10.1,
  go-oidc 3.21, go-jose 4.1.7, Prometheus client 1.25, `x/crypto` 0.58,
  `x/oauth2` 0.37 and YAML 3.0.6.
- Kubernetes integration: Kubernetes client libraries 0.37, controller-runtime
  0.25, gRPC 1.85 and Secrets Store CSI Driver 1.6.1, tested on Kubernetes 1.35.0.
- Every newly linked module version is recorded in the license manifest; see the
  [dependency review](../research/transitive-go-license-inventory.md#follow-up--2026-11-04-dependency-update).

**Building from source / 从源码构建**
- The core module now requires **Go 1.26**, because several updated
  dependencies need it and Go 1.25 is no longer supported. Releases and images
  keep the reviewed Go 1.26.10 toolchain, so published binaries are unaffected.
- `scripts/verify-release.mjs` and `scripts/verify-image.mjs` now read the MySQL
  driver's covered-source archive from the reviewed license manifest instead of
  expecting a fixed version.
- CI uses `actions/setup-node` 7.1.0 ([#17](https://github.com/viber-ops/configra/pull/17)).

## Upgrade from v1.3.0 / 从 v1.3.0 升级

1. Preserve the current binary/image and configuration and take the usual
   verified backup.
2. Restart Management, API and workers with the matching v1.3.1 build, and
   redeploy the v1.3.1 Kubernetes integration image if you use it. Cold-start
   configuration, ports, Master Key and service-account grants are unchanged.
3. No `migrate` step or new MySQL/ClickHouse DDL is required. The database
   remains schema **4**.
4. Reload the Management page.

从 v1.2.x 升级请先阅读 [v1.3.0](v1.3.0.md)；从更早版本升级，仍需依次完成 [v1.1.0](v1.1.0.md) 与 [v1.2.0](v1.2.0.md) 的迁移步骤。

## Rollback / 回退

v1.3.1 changes no stored data or configuration. Rolling back to v1.3.0 binaries
only restores the previous UI and libraries; no database action is needed.

## Verification

The release commit passed CI and the three-node Kubernetes acceptance
([run 41984279185](https://github.com/viber-ops/configra/actions/runs/41984279185)).
Its ten-minute capacity gate did not pass on GitHub's hosted runners that day:
every functional check passed, but slow runners pushed latency past the gate's
limits. The unchanged v1.3.0 code, which had passed the same gate twice earlier
that day, failed it at the same time on the same kind of runner
([run 41986915287](https://github.com/viber-ops/configra/actions/runs/41986915287):
warmup throughput 937/s against the 980/s floor), so these failures reflect the
runners rather than this release. The dependency update passed the full gate on
a healthy runner
([run 41972563625](https://github.com/viber-ops/configra/actions/runs/41972563625):
600,000/600,000 requests, every access event persisted, both leak scans clean);
the runner comparison is recorded in
[#41](https://github.com/viber-ops/configra/pull/41). Archives are built from the
tag, held as a draft and downloaded and verified before publication. Publication
does not upgrade or restart a user's production deployment automatically.
