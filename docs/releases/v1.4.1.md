# Configra v1.4.1

This patch stores single-line Vault Text values without leading and trailing
whitespace, so a pasted address such as `" http://service.example.com:8918"` no
longer resolves into a broken Config. It also fixes a v1.4.0 regression that
refused some scoped automation writes. It remains compatible with configra-go
v1.2.0. The MySQL schema stays at **4**, and no configuration change is needed.

本版解决 [#62](https://github.com/viber-ops/configra/issues/62)：单行 Text 值保存时自动去掉首尾空白，避免带空格的地址解析进 Config。
同时修复 v1.4.0 中部分 Scoped 写入被错误拒绝的问题。SDK 保持 v1.2.0；从 v1.4.0 升级不需要数据库结构迁移，也不需要修改配置。

## Changes / 变更

**Vault Text values without edge whitespace**
([#62](https://github.com/viber-ops/configra/issues/62), [#63](https://github.com/viber-ops/configra/pull/63))
- A single-line **Text** value loses its leading and trailing whitespace when it
  is saved. This covers spaces, tabs, line breaks, the full-width space and the
  other Unicode spaces, plus the invisible U+200B and U+FEFF. Reads and resolved
  Configs return the cleaned value, and spaces inside a value are kept.
- The rule applies on every write path: the Management UI and API, scoped
  writes, `configractl` and the YAML import draft.
- These are stored exactly as given:
  - Text that still contains a line break once its edges are removed, such as a
    certificate or a script;
  - Secret and File values;
  - values a scoped write did not submit;
  - restored revisions.
- A value of only whitespace becomes `""`. The editor no longer requires a Text
  value, matching the server, Config resolution and the import's `value: ""`,
  which v1.4.0 could not create from the form. Secrets still require a value.
- Existing values are not rewritten:
  - Revealed values with edge whitespace show an **Edge whitespace** badge.
  - The editor cleans a value when its field loses focus.
  - The editor lists what a save will clean in every Variant, without values,
    and **Remove now** cleans them without retyping.
- Saving a value that differs only by edge whitespace is `no_change`, so no
  revision is added.
- The editor warns, without showing the value, when a Secret starts or ends with
  whitespace.
- See the [UI notes](https://github.com/viber-ops/configra/blob/v1.4.1/docs/ui.md#vault-text-whitespace--vault-文本值的首尾空白).

**Scoped writes** ([#63](https://github.com/viber-ops/configra/pull/63))
- Since v1.4.0, Vault reads return Fields in the order they were added, while
  scoped writes compared them in key order. On an Item whose Fields were not in
  key order, a Token granted only some of the Item's Environments got
  `scope_forbidden` for a plain value change. That included `configractl vault
  field put`. Field definitions are now compared regardless of order.

**configractl**
- `vault field put --type secret` writes `{"warning":"secret_edge_whitespace"}`
  to stderr when the input starts or ends with whitespace or a line break, for
  example the newline `echo` adds. The value is not shown, and the Secret is still
  stored as given.

**API notes for integrations / 接口说明**
- `PUT /v1/vault-items/{namespace}/{item}` sends the whole Item, so saving an
  Item you just read also cleans its older single-line Text values in every
  Variant.
- A single-line Text value whose edge whitespace is meant to be there, such as
  a prefix ending in a space, is now trimmed. Store it in a Secret Field instead.
  A per-Field option to keep Text exactly as written is not part of this release.
- Retry an uncertain write with the same body. The Operation ID covers the bytes
  that were sent, not the cleaned value.

## Upgrade from v1.4.0 / 从 v1.4.0 升级

1. Preserve the current binary/image and configuration and take the usual
   verified backup.
2. Restart Management, API and workers with the matching v1.4.1 build, and
   redeploy the v1.4.1 Kubernetes integration image if you use it. Cold-start
   configuration, ports, Master Key and service-account grants are unchanged.
3. No `migrate` step or new MySQL/ClickHouse DDL is required. The database
   remains schema **4**.
4. Reload the Management page.

从 v1.3.x 升级请先阅读 [v1.4.0](v1.4.0.md)；从 v1.2.x 升级还需阅读 [v1.3.0](v1.3.0.md)；从更早版本升级，仍需依次完成 [v1.1.0](v1.1.0.md) 与 [v1.2.0](v1.2.0.md) 的迁移步骤。

## Rollback / 回退

v1.4.1 adds no tables or columns. Values it stored are ordinary Vault revisions
that v1.4.0 reads unchanged. Rolling back to v1.4.0 binaries stops trimming new
writes and brings back the scoped-write regression; no database action is
needed.

v1.4.1 没有新增表或字段；它保存的值是普通的 Vault 版本，v1.4.0 可直接读取。回退到 v1.4.0 后不再清理新写入的值，Scoped 写入问题也会恢复；不需要任何数据库操作。

  also passed, with p50 2.3 ms.

This release changes only Vault write paths, not the read path the gate measures.
