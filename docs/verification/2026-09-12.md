## Audit

The documentation fixture reproduced `client_certificate.issued` becoming `dead`
with `invalid_audit_payload`: a valid 64-character SHA-256 fingerprint exceeded
the decoder's 63-character Resource Key limit. The HTTP regression in
`scripts/docs-smoke.mjs audit` failed because the event was missing from Management
Audit. After typed-identifier validation was added and the worker restarted, the
original event was requeued and delivered on attempt 2 with its full fingerprint.
Recovery used no SQL rewrite or deletion.

Authenticated mutation rejections now record a generated Request ID, controlled
error code, actor and validated route metadata before returning an error. They
do not store bodies, query strings, raw URLs or unaccepted operation keys, and
do not reserve an OperationID. Errors after a committed storage audit retain that
logical audit without an extra gateway event. Invalid identifiers are omitted,
including when decoding older failed records. If a receipt cannot be stored, the
response becomes one value-free `503 audit_unavailable` envelope with the same
Request ID; no durable receipt is promised while its database is unavailable.
Unauthenticated requests and non-mutating preview/validation routes are outside
this mutation-audit scope.

| Live check | Result |
| --- | --- |
| Viewer mutation | `403 forbidden`, receipt searchable by Request ID |
| Malformed JSON / unknown field | `400 invalid_request`, value-free receipt |
| Missing / invalid OperationID | `422 validation_failed`, no OperationID reservation |
| CSRF / unsupported content type | `403 csrf_rejected` / `415 unsupported_media_type`, receipts found |
| Invalid certificate identifier | One logical validation audit, rejected identifier omitted |
| Receipt store unavailable | One `503 audit_unavailable`, no concatenated original error/value |
| Reuse after rejection | Admin successfully used the same OperationID |
| Accepted-operation replay | Original logical audit retained; no new business audit |
| Browser Audit page | Displays reason and Request ID; Request ID search works |

Go race/vet, full real-dependency integration and E2E suites passed against MySQL
8.0.22, ClickHouse and NATS; 42 browser tests passed in this audit run. An initial
combined integration run was invalidated by a demonstration worker consuming a
test NATS event and a missing backup fixture Compose project name. Stopping that
worker and supplying the fixture identity allowed both full suites to pass
without assertion changes.

[ADR-0031](../adr/0031-correlate-rejected-requests-without-reserving-operations.md)
requires coordinated Management worker rollout, not prolonged mixed-version
workers. ClickHouse request/error columns are added idempotently; old records
retain empty values. Recovery uses bounded pages, preserving event IDs and attempt
history, and requeues only strict-decoder-approved records. At-least-once delivery
can repeat physical rows for one logical event ID. Large recovery/fault-injection
drills and final release-image acceptance remain open.

## Documentation

Fresh server rc.1 (`99e471d`) and SDK rc.1 (`5bb89dc`) clones were tested in an
empty temporary parent. The disposable Compose project was
`configra-doc-check-20260912`, with real MySQL 8.0.22 amd64, NATS, ClickHouse and
Casdoor 3.158.0. The arm64 macOS host's Docker VM had 18 CPUs and 33,598,365,696
bytes of memory; no production or unrelated services were changed.

The unmodified rc.1 `make local-run` failed at MySQL `io_setup(): EAGAIN`, with
64,976 of 65,536 host AIO contexts in use. The development-only `compose.local.yaml`
overlay disabled native AIO and separated the local Compose project. All fixture
dependencies then became healthy. SQL confirmed version `8.0.22` and development
`innodb_use_native_aio=OFF`; the production/load base configuration was unchanged.
This fix is new source, not a change to the published rc.1 tag.

before seeding. It verifies HTTPS, keeps private artifacts owner-only and does
not print credentials or resolved values. It tests protocols, not browser dialogs.
Its observed credential audit warning led to the [audit repair above](#audit).

Both website languages now explain that stopping tmpfs database containers loses
data even without `down -v`. Backup guides include output-directory creation,
working directory, credential-file shape, access prerequisites and expected
filenames. Abstract homepage slogans were removed. All public guides have both
language routes; type checking and 32 static tests covered links, anchors,
same-page language switching, locale navigation and delivered license text.

This run did not verify full bilingual browser/visual behavior, every Management
dialog, a complete production Kubernetes install, every revised backup command,

capacity/leakage gate. Those requirements remain in the acceptance contract.
