# 2026-11-10 verification: Go 1.26.11 and compression-library security updates

Scope: the security branch on top of `main` (`89e57e2`, v1.3.1 plus #43 and #45).
This records the review behind the Go 1.26.11, brotli 1.2.7 and
klauspost/compress 1.20.2 updates. It is not release acceptance for capacity,
Kubernetes or production readiness.

## Why

CI on every branch started failing only its vulnerability gate.
`govulncheck@v1.7.0` reports three reachable advisories:

- **GO-2026-6859** (`net/http`, fixed in go1.26.11), in both the core and
  Kubernetes modules. When a body exceeds `MaxBytesReader`'s limit, an HTTP/1
  server sets `Connection: close` without synchronization. A handler that sets a
  header at the same time can crash the process.
- **GO-2026-6888** (`github.com/andybalholm/brotli`, fixed in 1.2.7): excessive
  memory when decompressing crafted streams.
- **GO-2026-6865** (`github.com/klauspost/compress`, fixed in 1.20.2): panic on
  two-block frames.

The two library updates are reviewed in the
[transitive inventory](../research/transitive-go-license-inventory.md).

  (from `go.dev/dl/?mode=json&include=all`). The same query reproduces the

  `sha256:dc40a13b61304647ed7e5d581d246b86413dfc29d63c6d018310feb93cd98fc0`.
  This supersedes Dependabot's rebuilt go1.26.10 digest in #46 and #47.
- All 40 files in `scripts/go-notices/files.txt`, and Go's `LICENSE`, are
  byte-identical between the go1.26.10 and go1.26.11 GOROOTs (`cmp`). The
  curated runtime notice bytes and the supplemental Go LICENSE hash in
  `reviewed.json` are therefore unchanged; only version strings and the archive
  hash in `SOURCE.md` change.
- All twelve package-selection digests match under go1.26.11.
- `go vet ./...` and `go test -race ./...` pass for both modules.
  `govulncheck@v1.7.0 ./...` reports no vulnerabilities.
