# v1.1.0 scoped-write verification — 2026-10-02

This record concerns Configra's scoped write tokens and the corresponding
configra-go write client. September's released capacity/Kubernetes evidence
remains attached to v1.0.1 and is not substituted for a new release gate.

## Local fixture and coverage

Host: macOS arm64, Go 1.25.13; disposable Compose dependencies are MySQL **8.0.22**,
NATS and ClickHouse from `deploy/compose.test.yaml`. The new SDK E2E uses real
MySQL persistence, HTTPS/mTLS, managed CA/client issuance and the NATS-to-ClickHouse
Access pipeline. Audit receipts are drained into the real ClickHouse store and
queried through Management.

`TestScopedWriteSDKWithRealMySQLNATSClickHouse` verifies:

- Administrator issuance requires MFA; signed OIDC/session tests separately
  verify `amr` evidence and reject role/UserInfo/header substitutes.
- Config and Namespace allowlists, Environment grants, and indirect Config
  references reject outside-scope reads/writes with 403.
- Config creation/update, optimistic conflicts, replay and retained history.
- Seventeen binary File uploads, field/item deletion with retained revisions,
  environment-specific reads and isolated writes to a shared Variant.
- Global schema/item changes cannot affect an outside-scope Environment.
- Read-only, certificate-bound deployment issuance inherits scopes and cannot
  mint writers, expand grants or bypass mTLS; one-time secrets are absent on replay.
- Deployment revocation removes both credentials; writer revocation cascades;
  expired/revoked credentials fail on already-created clients.
- The shipped operator runs in both testing and production, submitting all 17
  files in one snapshot and saving Token/bundle files with mode 0600.
- Audits retain public Token ID, action, object/Field, timestamp and TCP peer IP;
  replay produces one audit identity; secret/file values and exports stay absent.

`TestScopedTokenMigrationFromV2PreservesLegacyReadCredentials` reconstructs the
released v2 schema around an existing Token, rejects a wrong Master Key before
migration, verifies that API never migrates, and confirms v3 retains its grants,
non-expiry and Token-only mode. Scope-policy tests cover mandatory expiry, the
configured limit and omitted versus explicit empty allowlists/replay digests.

## Checks and failures

- Go race suites, vet and module verification pass locally for SDK and service;
  service integration/storage includes real backup/restore and rotation checks.
- All **52** browser regressions pass, including scoped issuance and MFA errors;
  UI license/SBOM tests and distribution/profile collector regressions pass.
- The initial complete integration run found a previous v2 migration assertion
  still hardcoding the latest schema as 2. It now also verifies both v2/v3 records.
- The cross-Environment operator run found that an absent Variant could not
  discover the existing Item's global revision. `expected_revision=0` now creates
  only an absent selected-Environment Variant under the Item lock. Existing
  Variants still require a matching revision; the subsequent scoped E2E passes.

Hosted CI/acceptance and published tag/archive URLs are added after their runs;
unfinished gates are not recorded as passed.
