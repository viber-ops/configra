# Distribution composition

Release builds and both image builds compose already-verified component evidence
into `SBOM.cdx.json` plus `INVENTORY.json`. The original per-module/UI SBOMs remain
unchanged and are referenced with their hashes. Component identities are merged
only when their versions, hashes, licenses and source identities agree.

The aggregate includes each executable, its Go module graph, the Go runtime,
embedded UI where applicable, and the system CA data/source material in images.
Native binary bundles do not include their host OS or its trust store. Databases,
OIDC, NATS, ClickHouse, Kubernetes/CSI driver and other operator-supplied services
are not represented as bundled software.

Every ordinary payload file is inventoried with its relative path, byte length,
mode and SHA-256. The SBOM records a digest of the input file set; the inventory
also records the generated SBOM and excludes only itself to avoid a self-hash
cycle. This is not an OCI image manifest digest or a signing/attestation system.

```sh
# From the source checkout; this test uses its own disposable fixture:
node --test scripts/compose-distribution.test.mjs

# Verify an extracted release bundle:
node scripts/verify-distribution.mjs /absolute/extracted/bundle INVENTORY.json

# Verify actual locally built images, including their exported filesystems:
make image-license-test
```

The image verifier accounts separately for Docker's init-layer files:
`.dockerenv`, `etc/hostname`, `etc/hosts`, `etc/resolv.conf`, `dev/console`, and
the exact `etc/mtab -> /proc/mounts` alias. The alias is checked but not extracted.
These are generated by the container runtime, not supplied by the image build;
all other files must match the inventory. All other links and special file kinds
are rejected. [Moby init-layer source](https://github.com/moby/moby/blob/master/daemon/initlayer/setup_unix.go)

Validation is not release approval: the complete production contract and current
candidate's operational/security evidence remain required.
